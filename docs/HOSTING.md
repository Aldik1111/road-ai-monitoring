# Доступ по ссылке через интернет

## Что подготовлено

В корне проекта находится `render.yaml`: конфигурация одного Node.js-сервиса Render с постоянным диском на 1 ГБ. Хранятся и SQLite, и загруженные материалы. Создание сервиса по этой конфигурации платное; стоимость сервиса, диска и трафика проверьте в Render перед подтверждением. Конфигурация сама по себе не создаёт сервис и не списывает деньги.

Сайт пока **не опубликован**: требуется аккаунт владельца, доступ Render к репозиторию с актуальным кодом и подтверждение платного тарифа. Публичная ссылка появится только после успешного деплоя.

Выбран небольшой тариф `0.5c-512mb` и ограничение одного видео 32 МБ. Это вариант для небольшой команды и коротких показов, не для массовой загрузки видео. Для длинных записей увеличьте ресурсы, объём диска и только затем лимит. Не включайте несколько экземпляров приложения: текущая архитектура использует одну SQLite и один локальный диск.

## Порядок размещения

1. Создайте аккаунт на https://render.com или войдите через GitHub. Пароли аккаунта, платёжные данные и API-ключи в чат не отправляйте.
2. Опубликуйте актуальные исходники в вашем GitHub-репозитории. В репозитории должны быть `render.yaml`, `package.json`, `server.mjs`, `lib/` и `public/`. Не загружайте `data/private`, видео, `.env` и базу. Ранее скачанный исходный репозиторий содержит только ТЗ; без новых файлов приложение не запустится.
3. В Render выберите **New → Blueprint**, подключите этот репозиторий. Используйте `render.yaml` из корня.
4. Проверьте выбранный план, диск и итоговую стоимость. Примените Blueprint, только если согласны с платными ресурсами.
5. Дождитесь состояния **Live**. Платформа выдаст HTTPS-адрес вида `https://<имя-сервиса>.onrender.com`. Компьютер разработчика после этого не должен оставаться включённым.
6. В закрытом разделе **Environment** сервиса найдите `OPERATOR_PASSWORD`, `DISPATCHER_PASSWORD`, `WORKER_PASSWORD`, `ADMIN_PASSWORD`. Blueprint генерирует разные случайные значения. Передайте нужным людям только пароль нужной роли по личному каналу. Пароль администратора оставьте владельцу.
7. Откройте ссылку, войдите, загрузите короткое тестовое видео и GPS, проверьте создание/закрытие заявки. Перезапустите сервис и проверьте сохранение записей.

Поддерживается и подключение Render к этому чату через доступную интеграцию. Подключение аккаунта не означает согласие с платным тарифом: перед созданием ресурсов нужно проверить его стоимость.

## Серверные настройки

| Переменная | Назначение |
|---|---|
| `NODE_ENV=production` | Публичный режим, HTTPS-cookie, отсутствие демонстрационного пароля |
| `HOST=0.0.0.0` | Прослушивание интерфейса контейнера; задаётся только на сервере |
| `PORT` | Порт выдаёт Render |
| `DATA_DIR=/var/data/road-ai` | База и файлы на постоянном диске |
| `MAX_VIDEO_MB=32` | Лимит видео; локально по умолчанию 140 |
| `RENDER_EXTERNAL_URL` | Автоматический внешний адрес Render |
| `PUBLIC_ORIGIN` | Необязательное переопределение внешнего HTTPS-адреса, например для своего домена |
| `*_PASSWORD` | Четыре разных случайных пароля ролей, минимум 16 символов |

Для своего домена добавьте его в Render и установите `PUBLIC_ORIGIN=https://ваш-домен`. Указанный origin должен точно совпадать с адресом, открытым пользователями; посторонние Origin отвергаются. Сертификат и входящий HTTPS обслуживает хостинг.

При запуске публичного режима сервер отказывается работать без сильных разных паролей и HTTPS-адреса. Старые демонстрационные пароли заменяются значениями переменных окружения, старые сессии соответствующих ролей аннулируются. Изменить пароль можно изменением переменной и перезапуском сервиса. В базе остаются хеши scrypt, не открытые пароли.

`GET /healthz` используется платформой для проверки работоспособности; не раскрывает содержимое базы. `GET /api/config` сообщает интерфейсу режим входа и лимит видео без секретов.

## Доступ и ограничения

Любой человек со ссылкой увидит страницу входа, но просмотр материалов и работа с ними требуют авторизации. Пока существуют четыре общие ролевые учётные записи, а не персональные приглашения. Для индивидуального аудита каждого сотрудника и отключения одного сотрудника отдельно нужен следующий этап: управление пользователями.

Видео и фото пока проверяются по сигнатурам, загрузки буферизуются в памяти. Не раздавайте учётные данные неизвестным людям. Сервер рассчитан на ограниченную команду, не на открытый публичный приём произвольных файлов. Диск 1 ГБ быстро заполнится видеозаписями; автоматической очистки нет. Перед показом следите за свободным местом и делайте резервные копии базы вместе с файлами.

Детектор по-прежнему демонстрационный. Размещение в интернете не меняет качество распознавания.

## Проверено локально

Синтаксис Node.js и 7 тестов прошли. Среди проверок: запуск публичного режима с нужными настройками, замена старого демо-пароля, аннулирование старых сессий, Secure-cookie, отклонение чужого Origin, health-check, полный цикл ремонта, сохранение данных и шаблоны интерфейса на двух языках. Реальный деплой Render пока не выполнялся.
