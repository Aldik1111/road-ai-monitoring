# Экспериментальный детектор ям

Подключён настоящий локальный инференс YOLO11n через ONNX Runtime CPU. OpenAI для видео не используется и его баланс не расходуется. Это прототип проверки видео, а не надёжная автоматическая оценка состояния дорог.

## Windows

В папке с package.json выполните (Node.js 24+):

```powershell
npm.cmd ci
npm.cmd run setup:detector
npm.cmd start
```

Установка зависимостей и модели требует интернета. После установки видео обрабатывается локально. Python и GPU не нужны. На текущем компьютере зависимости и модель уже установлены. После изменения кода перезапускайте сервер; для публичного доступа остановите старый Quick Tunnel через `npm.cmd run share:stop`, затем запустите `npm.cmd run share`. Его ссылка изменится.

1. Войдите как оператор и создайте новую поездку.
2. Загрузите исправное MP4 (2–600 секунд), GPS CSV и укажите время начала с часовым поясом.
3. **Не ставьте галочку создания тестовых карточек.** Без неё запускается модель. Галочка сохраняет прежний демонстрационный сценарий.
4. На странице поездок видны очередь, процент обработки и количество просмотренных кадров.
5. В очереди проверки появятся найденные кандидаты с меткой «AI · проверить», кадром, рамкой, оценкой уверенности и версией модели. GPS указывает приблизительное положение камеры, а не измеренную позицию ямы.
6. Оператор подтверждает или отклоняет находку. Создание и исполнение ремонта работают как раньше.

Ноль карточек не означает отсутствие ям. Неисправный файл получает ошибку, а не синтетические находки. Можно повторить неудачную обработку. Для готовой поездки повтор возвращает сохранённый результат и сохраняет решения оператора; повторная оценка другой моделью требует новой поездки.

## Источник и воспроизводимость

- Автор весов: tahaUgan, https://huggingface.co/tahaUgan/pothole-yolo11n
- Файл: `pothole2v_320.onnx`; версия репозитория `5cc2892b1366ca3c70d4ef4b13f1a940dddb2cc5`.
- SHA256: `c91b4211d06c915ae94519de9def87461703d612569d3ce239bf69bd7baa8c26`.
- Автор указывает лицензию CC BY 4.0. Атрибуция сохранена здесь; происхождение обучающей выборки и качество независимо не подтверждены. Перед коммерческим использованием отдельно проверьте условия весов и обучающих данных.
- Из классов `Pothole` и `Sewage-Manhole` используется только `Pothole` (0).
- ONNX Runtime (MIT), sharp (Apache-2.0), ffmpeg-static (GPL-3.0-or-later; условия конкретной сборки FFmpeg также применимы). Зависимости зафиксированы package-lock.json. Бинарные файлы и модель в исходный архив не входят, их получает установщик.

Код проверяет хеш модели, размер входа 320×320 и выход [1,6,2100]. Декодируется 2 кадра/с, изображение сохраняет пропорции с полями. Рамки относятся к сохранённому квадратному кадру. Порог уверенности 0.45, NMS IoU 0.45. Время кадра — временная сетка 500 мс, не точный момент появления дефекта. На переменной частоте кадров выборка приблизительная. Соседние рамки объединяются по пересечению и промежутку до 1.2 с; это простая эвристика, возможны повторы и неверные объединения.

Одновременно обрабатывается одна поездка в отдельном процессе. HTTP-сервер остаётся доступным; инференс использует 2 CPU-потока, FFmpeg — 1. Максимум 1200 кадров, 2000 рамок, 15 минут на поездку. Используйте один сервер на один DATA_DIR. Результаты публикуются одной транзакцией. После перезапуска незавершённая поездка возвращается в очередь. Временные JPEG после сбоя могут остаться в закрытой папке файлов; при повторе имена повторно используются.

## Что проверено и что не готово

Автотесты проверяют настоящий FFmpeg + ONNX на двухсекундном пустом видео, загрузку через HTTP с GPS, прогресс, нулевой результат, повтор, доступность сервера и отказ на повреждённом MP4. Отдельно проверяются разбор рамок, исключение люков, NMS и группировка нескольких одновременных объектов. Проверки синтетических тензоров не доказывают качество распознавания.

Дополнительная исследовательская проверка: три 4-секундных фрагмента из открытого набора Warren Stading, Pothole Detection Lab, https://github.com/warstad11/pothole/tree/4e6c793c9c724affb879e5fca63373a4579ba76f/dataset (CC BY-NC 4.0 и условия автора; видео не распространяются с проектом). Фрагменты `drive_02_clip_004`, `drive_03_clip_007`, `drive_03_clip_010` размечены автором как pothole. При 2 кадрах/с и пороге 0.45 эта модель дала **0 находок во всех трёх**. Это свидетельство пропусков, а не подтверждение пригодности. Независимую покадровую разметку и полноценный precision/recall мы не выполняли.

Перед рабочим применением нужен дневной фрагмент вашей камеры с GPS и ручной проверкой всех ям, включая пропуски. Затем следует подобрать или дообучить модель и проверить её на другом маршруте. Текущая модель обозначена экспериментальной, автоматические ремонтные задания без решения оператора не создаются.
