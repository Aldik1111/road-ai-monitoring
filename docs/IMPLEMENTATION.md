# Реализация MVP

Обновление: дизайн переведён на голубую и золотую палитру. Подготовлен публичный режим и Blueprint Render; сайт ещё не развёрнут. Инструкция — `HOSTING.md`. Текущий набор включает 7 проходящих тестов, в том числе проверки HTTPS-конфигурации, замены демо-паролей, аннулирования сессий и защиты Origin. Ниже базовые ограничения MVP; для интернет-режима приоритет имеют настройки HOSTING.md.

## Выбор стека

Node.js 24, встроенные HTTP и SQLite (`node:sqlite`), обычные HTML/CSS/JavaScript. Нет сторонних runtime-зависимостей, сборщика, npm-install, Docker или Python. Один процесс обслуживает API, файлы, интерфейс и фоновую очередь. SQLite WAL сохраняет состояние между запусками. Транзакции и уникальный индекс кандидата защищают создание заявки.

Приложение рассчитано на локальный показ на одном компьютере, а не на публичный многопользовательский сервис. Учётные записи заранее заданы. Пароли хешируются scrypt, сессии хранятся в SQLite, cookie — HttpOnly/SameSite. Роли проверяются сервером. Администратор выполняет функции оператора/диспетчера, но для демонстрации исполнения используется отдельная учётная запись worker.

## Файлы

- `server.mjs`: API, сессии, хранение, очередь, состояния, приём материалов.
- `lib/domain.mjs`: GPS, время, группировка кадров.
- `public/app.js`: экраны, словари ru/kk, формы, карта.
- `public/style.css`: адаптивный интерфейс.
- `public/demo-frame.svg`: синтетическая иллюстрация с тестовой рамкой.
- `public/sample-gps.csv`: синтетический пример GPS.
- `tests/`: модульные проверки и сквозной тест API с отдельной базой.
- `.vscode/`: запуск F5 и задача тестирования.

## API

Все сущности находятся под `/api`. Кроме входа, требуется сессионная cookie. Мутации сущностей требуют `Idempotency-Key` (8–100 символов). Ключи сохраняются с актором и путём запроса; повтор возвращает прежний результат. Один ключ предназначен для одного действия с неизменным содержимым.

| Метод и путь | Назначение |
|---|---|
| POST `/api/login` | `{username,password}` |
| GET `/api/me` | Текущая роль |
| POST `/api/logout` | Завершение сессии |
| GET `/api/state` | Данные интерфейса |
| POST `/api/trips` | Multipart: video, gps, route_name, camera_description, started_at, duration, demo |
| GET `/api/trips[/id]` | Поездки и статус |
| POST `/api/trips/:id/retry` | Повтор обработки без удаления решений |
| GET `/api/candidates[/id]` | Очередь и карточки |
| POST `/api/candidates/:id/position` | `{lat,lon,reason}` |
| POST `/api/candidates/:id/decision` | `{decision,reason?,target_id?}` |
| GET `/api/orders[/id]` | Задания |
| PATCH `/api/orders/:id` | `{status,assignee?,due_at?,reason?}` |
| POST `/api/orders/:id/photo` | Multipart: photo PNG/JPEG |
| GET `/api/metrics` | Счётчики и длительности |

Ошибка: `{code,message,retryable}`. `message` содержит стабильный ключ, интерфейс переводит его на выбранный язык. Имена полей и статусы соответствуют ТЗ. Сведения о GPS хранятся вместе с поездкой. Сущности хранятся как JSON-записи SQLite; отдельная таблица `orders_unique` закрепляет уникальность ремонта по кандидату.

## Очередь и детектор

Сервер опрашивает устойчивую очередь каждые 500 мс. При старте незавершённые uploaded/processing переводятся в queued. Сейчас работает только синхронный, короткий демонстрационный адаптер. Для настоящего длительного инференса понадобится отдельный worker-процесс с очередью и ограничением ресурсов.

Нет весов и разрешённого проверочного видеомаршрута: реальный детектор не запускается и его качество не заявляется. Только при явном согласии пользователя `demo=true` создаются пять фиксированных тестовых FrameDetection на 1, 1.6, 7, 7.6 и 13 секунде в пределах длительности видео. `origin=test`, `model_version=demo-fixture-v1`; группировка даёт до трёх кандидатов. Кадры представлены одной синтетической иллюстрацией, не извлечёнными кадрами исходного видео. Исходное видео проигрывается отдельно с нужной временной отметки.

Группировка использует временную близость и близость рамок. Это демонстрационная эвристика, не проверенный трекер реальных дефектов. Повтор с той же версией использует устойчивые ID и сохраняет решения.

## Ограничения

- MP4 до 140 МБ в интерфейсе; общий multipart-запрос до 150 МБ, фото до 8 МБ. Запрос временно буферизуется в памяти. Для больших видеопотоков нужен потоковый приём и отдельное хранилище.
- Сервер проверяет расширение и сигнатуру MP4, браузер проверяет возможность чтения метаданных и длительность. Полный серверный анализ контейнера/кодеков и антивирусная проверка не реализованы; прямой API-клиент может передать неверную длительность. JPEG/PNG проверяются по сигнатуре, не декодируются сервером.
- Для короткого показа разрешены видео 2–600 секунд (явное расширение нижней границы предположения ТЗ в 2 минуты).
- Обследование — очередь с причиной, без отдельного WorkOrder вида survey, что допускается минимальным вариантом ТЗ.
- Карта использует растровые тайлы OpenStreetMap и кнопки перемещения/масштаба; интернет нужен только для подложки и необязательного шрифта. Неизвестные координаты не отображаются как точные маркеры.
- Доля пригодного видео и пропуски не измеряются; API возвращает null. Время от кадра до заявки относится к тестовым карточкам и не доказывает KPI менее 24 часов от появления ямы.
- Нет публичного развёртывания, управления пользователями, массового импорта, реального обучения/инференса, автоматического удаления старых загрузок и серверного транскодирования.
- Изменение языка перерисовывает текущую форму: выбирайте язык до её заполнения.

## Проверено 12.10.2026

`npm.cmd run check`: синтаксис сервера и интерфейса прошёл проверку.

`node --test tests/*.test.mjs`: **5 тестов прошли**. Сквозной тест реально обращается к отдельному HTTP-серверу и проверяет загрузку multipart, обработку, группировку, роли, обязательные причины, исправление с сохранением исходной точки, обследование, отклонение, объединение, повтор подтверждения и обработки без дублей, назначение, фото, возврат, закрытие, Range-видео, ошибку отсутствующего детектора и сохранность после перезапуска. Дополнительно проверяется генерация всех экранов для двух языков и четырёх ролей, равенство ключей переводов и экранирование пользовательского текста. Это программная проверка шаблонов, не визуальная проверка в браузере.

API-тест использует минимальную тестовую сигнатуру MP4, а не декодируемое видео. Воспроизведение реального видео и визуальная проверка браузером в этой среде не подтверждены: встроенный браузер не смог подключиться к localhost, затем его политика заблокировала обращение к внутренней странице ошибки. Обычный браузер пользователя и ручной сценарий из RUNNING.md остаются необходимой проверкой перед показом.
